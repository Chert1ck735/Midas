# Разработка

## Окружение и проверки

Из корня проекта, Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
cp .env.example .env
python -m pytest -q
```

Зависимости закреплены в `pyproject.toml` и `requirements.txt`; обновляйте оба файла
согласованно. `requirements.txt` используется при сборке Docker-образа.
GitLab CI настроен в `.gitlab-ci.yml`: тесты запускаются на Python 3.11 и 3.12
для веток и merge requests. Для выполнения заданий нужен доступный GitLab Runner.
Дополнительные средства чтения parquet (`pandas`, `pyarrow` или `fastparquet`) могут
потребоваться для локальных выгрузок ALGOPACK; этот сценарий не входит в быстрый старт.

## Изменения стратегии

В описании изменения указывайте, какие сигналы или ограничения поменялись.
Для изменений расчётов и исполнения добавляйте проверку соответствующего сценария.
Сравнивайте бэктесты на одинаковом датасете, периоде, составе инструментов и издержках.
Сохраняйте конфигурацию и версии модели рядом с результатом; обучение и оценку
разделяйте по времени. Изменения README проверяйте по действительным CLI и конфигурации.

## Состав репозитория

В Git входят исходники, тесты, документация, конфигурационные шаблоны и две модели
из явного списка в `.gitignore`. Датасеты, выгрузки, состояние портфеля, журналы,
отчёты, экспериментальные модели и локальные `.env` остаются вне репозитория.
Файлы `.joblib` должны сопровождаться метаданными; не добавляйте модели из
непроверенных источников.

Перед первым коммитом после инициализации Git проверьте состав файлов:

```bash
git status --short --untracked-files=all
git add --dry-run .
```

`.gitignore` не скрывает ранее добавленные в Git файлы. Если секрет уже попадал
в историю, его нужно отозвать у провайдера; удаления из рабочей директории недостаточно.
В сборку Docker `.env` не передаётся. Рабочие ключи задаются только при запуске.
