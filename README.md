
# Midas — MOEX Trading Agent

Репозиторий: [chert1ck735/midas](https://gitlab.com/chert1ck735/midas).

Исследовательский торговый агент для Московской биржи, созданный для хакатона ArenaGo.
Проект объединяет стратегию на технических индикаторах, ML-фильтр сигналов и отдельный
слой контроля риска. Опциональная LLM-супервизия интерпретирует рыночный контекст,
объясняет сделки и корректирует разрешённые параметры.

Репозиторий содержит код агента, две обученные LightGBM-модели, инструменты для
сборки датасетов, обучения и бэктеста, а также разборы экспериментов.
Это исследовательский прототип: доходность на истории не подтверждает будущую
доходность или готовность к торговле на реальном счёте.

## Что умеет

- Получать свечи и макроиндексы через MOEX ISS; использовать ALGOPACK для микроструктуры.
- Рассчитывать RSI, MACD, Bollinger Bands, ATR и определять режим рынка.
- Генерировать сигналы для длинных и коротких позиций; фильтровать их LightGBM-моделями.
- Ограничивать размер позиции, экспозицию, дневной убыток и просадку; учитывать лотность,
  стопы, задержку между сделками и аварийное отключение отправки заявок.
- Работать в демонстрационном режиме, вести paper-портфель на базе ArenaGo
  или отправлять заявки в API ArenaGo.
- Записывать решения, состояние и отчёты; восстанавливать состояние после перезапуска.
- Собирать исторический датасет, обучать модели и проигрывать стратегию с издержками.

## Быстрый старт

Нужен **Python 3.11+**. Выполняйте команды из корня скачанного проекта.
Для первого запуска ключи ArenaGo, ALGOPACK и LLM не нужны.

```bash
git clone https://gitlab.com/chert1ck555/midas.git
cd midas

python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
cp .env.example .env

# Один цикл на синтетических свечах, без обращения к рыночным API
MARKET_DATA_PROVIDER=sample NEWS_ENABLED=false python -m moex_agent --once

# Один цикл на котировках MOEX ISS; нужен доступ к сети
python -m moex_agent --once

# Непрерывная работа (Ctrl+C для остановки)
python -m moex_agent
```

В Windows PowerShell активация окружения — `.venv\Scripts\Activate.ps1`,
копирование конфигурации — `Copy-Item .env.example .env`.
Для синтетического режима задайте `$env:MARKET_DATA_PROVIDER="sample"` и
`$env:NEWS_ENABLED="false"`; перед переходом на ISS удалите эти переменные
через `Remove-Item Env:MARKET_DATA_PROVIDER, Env:NEWS_ENABLED`.

В `.env.example` выставлены `DRY_RUN=true`, `PAPER_TRADING=false`,
`MARKET_DATA_PROVIDER=iss` и `LLM_ENABLED=false`.
Агент использует демонстрационный портфель с фиксированными остатками и
**не отправляет заявки**. Такой dry-run проверяет расчёт решений, но не моделирует
накопление портфеля и исполнение сделок. Вне часов работы рынка непрерывный цикл
ожидает открытия; `--once` позволяет выполнить цикл сразу.

Состояние и журналы появятся в `data/`. Если включённая ML-модель не загрузилась, новые входы блокируются;
выходы из позиций остаются доступны. Проверяйте предупреждения в логах.
На Linux при ошибке `libgomp.so.1` установите OpenMP runtime
(для Debian/Ubuntu — `sudo apt-get install libgomp1`).

## Режимы и настройки

| Режим | Настройки | Нужен ключ ArenaGo | Поведение |
|---|---|---|---|
| Демонстрация | `DRY_RUN=true`, `PAPER_TRADING=false` | Нет | Фиксированный тестовый портфель, заявки только в журнале |
| Paper | `DRY_RUN=true`, `PAPER_TRADING=true` | Да | Читает портфель ArenaGo, ведёт локальный paper-учёт без отправки заявок |
| Отправка заявок | `DRY_RUN=false`, `PAPER_TRADING=false` | Да | Отправляет заявки через API ArenaGo |

Флаг `--live` также отключает оба защитных режима и дополнительно требует
`I_REALLY_WANT_LIVE_TRADING=yes`. Если оба режима отключены непосредственно в `.env`,
эта проверка флага не применяется. Для подключения ArenaGo нужны `SANDBOX_API_KEY`,
правильные `ARENAGO_BASE_URL` и `BOT_NAME`, соответствующий портфелю пользователя.
Адаптер реализован для ArenaGo; интеграций с другими брокерами в проекте нет.

Основные параметры доступны в [.env.example](.env.example), полный список и значения
по умолчанию — в [config.py](src/moex_agent/config.py).

| Переменная | Назначение |
|---|---|
| `MARKET_DATA_PROVIDER` | `sample` — синтетические свечи; `iss` — MOEX ISS; `algopack` — ALGOPACK |
| `MOEX_ALGO_TOKEN` | Токен для ALGOPACK; для ISS не требуется |
| `DATA_DIR` | Каталог состояния, журналов и отчётов; по умолчанию `./data` |
| `POLL_INTERVAL_SECONDS` | Интервал торгового цикла, по умолчанию 30 секунд |
| `ML_FILTER_ENABLED`, `ML_MODEL_PATH` | Включение и путь модели для лонгов |
| `ML_MIN_UP_PROBABILITY` | Порог модели для лонгов; в шаблоне явно указан текущий дефолт `0.58` |
| `ENABLE_SHORTS`, `ML_SHORT_MODEL_PATH` | Включение шортов и путь модели для них |
| `MAX_POSITION_PCT`, `MAX_PORTFOLIO_EXPOSURE_PCT` | Лимиты позиции и общей экспозиции |
| `MAX_DAILY_LOSS_PCT`, `MAX_DRAWDOWN_PCT` | Лимиты дневного убытка и просадки |
| `LLM_ENABLED`, `POLZA_API_KEY`, `POLZA_BASE_URL` | Включение и подключение LLM |

`.env.example` — конфигурация для знакомства с программой. Она **не повторяет**
исследовательскую конфигурацию из результатов ниже. У `Settings` без `.env` также
другие дефолты: например, провайдер `algopack` и включённый paper-режим, поэтому
не пропускайте копирование шаблона.

### LLM-супервизия

LLM не генерирует заявки напрямую, но может влиять на допуск входов, размер позиций
и параметры стратегии. `brief` обновляет рыночный контекст (TTL по умолчанию 3600 секунд),
`mid_review` пересматривает режим сессии, `auto_tuner` меняет параметры в заданных
границах, `explainer` и `daily_retro` объясняют сделки и результаты дня.

Для подключения укажите в `.env`:

```dotenv
LLM_ENABLED=true
POLZA_API_KEY=<ваш ключ>
POLZA_BASE_URL=https://api.polza.ai
```

Имена моделей задаются через `LLM_MODEL_FAST`, `LLM_MODEL_BRIEF`,
`LLM_MODEL_BRIEF_FALLBACK`, `LLM_MODEL_PREMIUM` и `LLM_MODEL_MID_REVIEW`.
Доступность моделей зависит от выбранного сервиса.

Клиент поддерживает OpenAI-совместимый URL, к которому добавляет `/v1/chat/completions`.
Однако главный цикл и отдельные модули супервизии проверяют наличие `POLZA_API_KEY`:
локальная LLM без ключа сейчас не подключается только сменой URL.
`auto_tuner` и `mid_review` могут переписывать `.env`; это нужно учитывать при
сравнении экспериментов и настройке контейнера.

## Как устроен агент

```text
MOEX ISS / ALGOPACK / синтетические свечи
                  |
          индикаторы и режим рынка
                  |
          стратегия входов и выходов
                  |
          ML-фильтр качества сигнала
                  |
          риск-лимиты и размер заявки
                  |
          ArenaGo / paper / dry-run
                  |
          JSONL-журналы и отчёты

LLM-контекст и супервизия -> параметры и ограничения стратегии
```

Торговый сигнал строится по числовым правилам. Модель оценивает его качество,
риск-слой проверяет допустимость заявки, адаптер отвечает за отправку.
Бэктест проигрывает детерминированную часть на готовом датасете;
эффект LLM-супервизии таким бэктестом не измеряется.

## Исторические результаты и ограничения

В [журнале экспериментов](docs/experiments.md) зафиксированы следующие результаты
на 20 бумагах за **2023-01-01 — 2026-07-01**, при начальном капитале 1 млн ₽.
Модель издержек: 5 б.п. комиссии и 5 б.п. проскальзывания на каждое исполнение
(20 б.п. от одинакового размера позиции за полный вход и выход).

| Метрика | Базовый прогон v5/v2 | Выбранная конфигурация |
|---|---:|---:|
| Порог лонгов | 0.65 | 0.92 |
| Шорты | Включены | Выключены |
| Докупки | Выключены | Выключены |
| Доходность за весь период | −38.24% | +4.02% |
| Максимальная просадка | 38.78% | 2.20% |
| Годовой Sharpe | −4.17 | 0.99 |
| Profit factor | 0.836 | 1.21 |
| Число сделок по учёту бэктеста | 18 675 | 3 058 |

Вывод исследования — частая торговля съедала небольшой валовой результат издержками.
Повышение порога и отключение шортов снизили оборот. Это результат выбора конфигурации
по историческим данным, а статистически значимое преимущество не установлено.

В репозиторий включены модели `lgbm_buy_filter_v5` и `lgbm_short_filter_v2`
(по 25 признаков, без микроструктуры). В их `*.meta.json` сохранены параметры обучения
и метрики holdout ROC-AUC: примерно **0.854** и **0.836**.
ROC-AUC характеризует ранжирование, а не доходность или калибровку вероятностей.

Исходные датасеты, журналы сделок и JSON-отчёты прогонов **не включены**.
Таблица выше перенесена из исследовательских заметок; проверить эти числа
одним запуском из чистой копии нельзя. Для точного повторения нужны исходные
данные, версии моделей и параметры конкретного прогона. Новая загрузка истории
может дать другой состав данных; предобученную модель нельзя считать независимой
проверкой на периоде, использованном при её обучении.

## Датасет, бэктест и обучение

Пример сборки истории через ISS с фиксированными датами:

```bash
python -m moex_agent.ml_offline_dataset --iss \
  --start 2023-01-01 --end 2026-07-01 \
  --target-mode triple_barrier --horizon-steps 9 \
  --barrier-up 0.010 --barrier-down 0.007 \
  --dataset data/logs/ml_dataset_iss.jsonl
```

Загрузка всей истории по 20 бумагам может занять значительное время.
Повторный запуск дописывает датасет; `--replace` пересоздаёт указанный файл.
Это пример построения нового датасета, а не восстановление оригинального.

Прогон с параметрами выбранной исследовательской конфигурации:

```bash
python -m moex_agent.backtest --dataset data/logs/ml_dataset_iss.jsonl \
  --ml-model data/models/lgbm_buy_filter_v5.joblib \
  --ml-threshold 0.92 --no-scale-in \
  --stop-loss-pct 0.012 --take-profit-pct 0.025 \
  --slippage-bps 5 --commission-bps 5 \
  --output data/backtests/iss_long_only.json \
  --dump-trades data/backtests/iss_long_only_trades.csv
```

Шорты в CLI бэктеста выключены, пока не передан `--enable-shorts`.
Параметры бэктеста задаются его аргументами и `BacktestConfig`, а не автоматически
переносятся из всех торговых настроек `.env`.

Обучение новой модели без перезаписи поставляемых артефактов:

```bash
python -m moex_agent.ml_baseline --dataset data/logs/ml_dataset_iss.jsonl \
  --task binary_up --cv-folds 5 --embargo-candles 10 \
  --no-microstructure --output data/models/experimental_buy_filter.joblib
```

Рядом с моделью создаётся `*.meta.json`. Экспериментальные модели и датасеты
исключены из Git. Загрузчик использует формат `joblib`: открывайте только модели
из доверенного источника, поскольку десериализация может выполнять Python-код.

## Docker

```bash
docker build -t moex-trading-agent .
docker run --rm --env-file .env -e DATA_DIR=/data -v moex-agent-data:/data \
  moex-trading-agent python -m moex_agent --once
```

Образ содержит код и поставляемые модели. `.env` и секреты исключены из контекста
сборки; настройки передаются при запуске через `--env-file` или `-e`.
Каталог состояния внутри контейнера — `/data`, для сохранения используется volume.
В команде `-e DATA_DIR=/data` переопределяет локальное значение из `.env`.

LLM-супервизоры переписывают `/app/.env`, а не файл, переданный через `--env-file`.
Этот файл без отдельного тома не сохраняется при удалении контейнера; приведённая
команда предназначена для демонстрационного запуска без LLM.

## Проверки и отчёты

```bash
python -m pytest -q
python -m moex_agent.monitor
python -m moex_agent.report --all
```

`monitor` читает локальные журналы и состояние. `report` записывает Markdown-отчёт
в `data/reports/`; без `--all` он учитывает только paper-записи.
Тесты покрывают лотность выходов, учёт коротких позиций, свежесть свечей
с разными часовыми поясами и загрузку поставляемых моделей; полного покрытия
торгового цикла и внешних API нет. GitLab CI запускает тесты на Python 3.11 и 3.12;
для зеркала на GitHub также сохранён workflow GitHub Actions.

## Структура проекта

```text
src/moex_agent/
  app.py                  торговый цикл и планировщик
  config.py               конфигурация из переменных окружения и .env
  market_data.py          ALGOPACK и синтетические свечи
  moex_iss.py              свечи и индексы MOEX ISS
  indicators.py           технические индикаторы
  regime.py, strategy.py  режим рынка и сигналы
  ml_features.py          признаки для обучения и инференса
  ml_filter.py            загрузка и применение моделей
  risk.py                 риск-правила и размер заявки
  arena_client.py         адаптер API ArenaGo
  paper.py                paper-учёт
  ml_offline_dataset.py   исторический датасет и разметка
  ml_baseline.py          обучение LightGBM и временная валидация
  backtest.py             симуляция с издержками
  llm/                    клиент, brief, новости и объяснения
  mid_review.py           пересмотр режима сессии
  auto_tuner.py           ограниченная адаптация параметров
  daily_retro.py          разбор дня
  monitor.py, report.py   просмотр состояния и отчёты
data/models/             две поставляемые модели и их метаданные
docs/                    методология и история экспериментов
tests/                   тесты лотности и шортов
```

`sweep_oborot.py` — старый исследовательский скрипт с жёстко заданной моделью v4,
которая в поставку не входит. Для новых прогонов используйте CLI `backtest`.
